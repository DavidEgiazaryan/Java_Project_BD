# Лабораторная работа 2. Упрощённая СУБД

## Текущее состояние

В базе две связанные таблицы. В консоли можно вставить одну или несколько записей, выбрать столбцы и строки по условию, обновить столбец или удалить подходящие записи. Программа показывает результаты выборки в виде таблицы.

Перед изменением проверяются типы, обязательные поля, первичные и внешние ключи. Если одна запись нарушает правила, вся операция отклоняется. Даты передаются как `java.util.Date` и сравниваются по календарному дню в UTC. Класс `SqlParser` разбирает запросы и проверяет имена столбцов, число значений и их типы по схеме базы.

## Запуск

В IntelliJ IDEA откройте `Main.java` и запустите метод `main` без аргументов. Нужен JDK 8 или новее. При первом запуске программа создаёт `database.ser` с пустыми таблицами в рабочей папке конфигурации запуска. При следующих запусках она загружает этот файл.

В окне **Run** после приглашения `sql>` вводите по одному SQL-запросу на строку. Завершайте запрос точкой с запятой. Команды `EXIT` и `EXIT;` закрывают консоль. Если запрос завершился ошибкой, программа показывает причину и принимает следующий запрос.

Чтобы заполнить пустую базу демонстрационными данными, укажите `--demo` в поле **Program arguments** конфигурации запуска IntelliJ IDEA. Демонстрация добавляет Toyota и два автомобиля, обновляет цену Corolla, затем удаляет Camry. Чтобы посмотреть сохранённые записи, запустите программу снова без аргумента и введите `SELECT * FROM cars;`.

Для проверки запроса передайте его через `--parse` в поле **Program arguments**.

```text
--parse "SELECT model, price FROM cars WHERE price > 20000;"
```

В этом режиме программа проверяет запрос по схеме `brands` и `cars` и выводит результат разбора или позицию ошибки. Для выполнения запроса используется обычный запуск.

## Операции из Java

| Метод | Назначение |
| --- | --- |
| `insert(table, row)` | Добавляет запись в порядке столбцов |
| `insert(table, values)` | Добавляет запись по карте «имя столбца → значение» |
| `insertAll(table, rows)` | Добавляет несколько записей одной операцией |
| `select(table, condition)` | Возвращает подходящие записи |
| `update(table, column, value, condition)` | Обновляет значение и возвращает число подходящих записей |
| `delete(table, condition)` | Удаляет подходящие записи и возвращает их число |

Объект `Condition` задаёт имя столбца, оператор сравнения и значение. `null` вместо условия означает все записи. При ошибке метод выбрасывает `IllegalArgumentException` с причиной. После успешного изменения программа вызывает `DatabaseFile.save`, чтобы записать состояние на диск.

## Предметная область

База данных автосалона содержит две связанные таблицы: марки автомобилей и автомобили. Одной марке могут соответствовать несколько автомобилей.

### Таблица brands

| Столбец | Тип | Обязательный | Назначение |
| --- | --- | --- | --- |
| id | INTEGER | да | Первичный ключ марки |
| name | STRING | нет | Название марки |

### Таблица cars

| Столбец | Тип | Обязательный | Назначение |
| --- | --- | --- | --- |
| id | INTEGER | да | Первичный ключ автомобиля |
| brand_id | INTEGER | да | Ссылка на brands.id |
| model | STRING | нет | Название модели |
| price | DOUBLE | нет | Цена |
| production_date | DATE | нет | Дата производства |
| available | BOOLEAN | нет | Признак наличия |

Порядок столбцов в таблицах именно такой, как в таблицах выше. Все пять типов из задания представлены в таблице cars.

## Типы и запись значений

- INTEGER — целое число в диапазоне Java int, например 1 или -12.
- DOUBLE — конечное число с плавающей точкой. Допускаются, например, 25000.0, 30000 и 2.5e4.
- STRING — текст в одинарных кавычках, например 'Toyota Camry'. Кавычка внутри строки записывается как две одинарные кавычки: 'O''Brien'.
- DATE — календарная дата в одинарных кавычках в формате 'ГГГГ-ММ-ДД', например '2024-05-17'. Некорректные даты отклоняются.
- BOOLEAN — TRUE или FALSE без кавычек; регистр букв не важен.
- NULL обозначает отсутствие значения и разрешён только в необязательных столбцах. Это не строка 'NULL'.

Имена команд и служебных слов нечувствительны к регистру. Имена таблиц и столбцов в этом проекте задаются строчными латинскими буквами; при разборе запросов их регистр не учитывается. Содержимое строк сохраняется с исходным регистром.

## Ключи и ограничения

1. Первичный ключ в каждой таблице обязателен и уникален в пределах этой таблицы.
2. cars.brand_id обязателен и должен ссылаться на существующий brands.id.
3. Удаление или изменение brands.id отклоняется, если на эту марку ссылается хотя бы один автомобиль. Удаление автомобиля не удаляет марку.
4. При изменении cars.id и cars.brand_id заново проверяются соответственно уникальность и наличие связанной марки.
5. Цена не может быть отрицательной. Нулевое значение и NULL допустимы.
6. При ошибке команда целиком отклоняется и данные остаются без изменений, в том числе при обработке нескольких записей.

## Поддерживаемые запросы

Консоль выполняет INSERT INTO, SELECT, UPDATE и DELETE. Команды CREATE TABLE, DROP TABLE и CREATE INDEX относятся к последующим дополнительным этапам.

- INSERT INTO table VALUES (...) задаёт значение для каждого столбца в порядке схемы.
- INSERT INTO table (column, ...) VALUES (...) задаёт значения перечисленных столбцов; пропущенные необязательные поля получают NULL. Пропуск обязательного поля — ошибка.
- Для нескольких записей в одном INSERT после VALUES перечисляются наборы значений в скобках через запятую.
- SELECT допускает * или список столбцов, а также необязательный WHERE с одним условием.
- UPDATE изменяет одно поле SET для всех записей, подходящих под необязательное условие WHERE. Без WHERE изменяются все записи.
- DELETE удаляет все записи, подходящие под необязательное условие WHERE. Без WHERE удаляются все записи.
- Условие имеет вид «столбец оператор значение». Поддерживаются =, !=, <, >, <= и >=. Порядковые сравнения предусмотрены для INTEGER, DOUBLE, STRING и DATE; для BOOLEAN — только = и !=. Для строк применяется сравнение с учётом регистра.
- Сравнение любого значения с NULL через перечисленные операторы не считается истинным. Специальные выражения IS NULL и IS NOT NULL пока не предусмотрены.
- Число значений должно совпадать с числом указанных столбцов; повтор столбца, неизвестные имена и несовместимые типы являются ошибками.

## Примеры запросов

```sql
INSERT INTO brands VALUES (1, 'Toyota');
INSERT INTO cars VALUES (1, 1, 'Camry', 25000.0, '2024-05-17', TRUE);
INSERT INTO cars (id, brand_id, model) VALUES (2, 1, 'Corolla');
SELECT * FROM cars;
SELECT model, price FROM cars WHERE price > 20000;
UPDATE cars SET price = 30000 WHERE id = 2;
DELETE FROM cars WHERE model = 'Camry';
```

В запросе для Corolla пропущенные поля price, production_date и available получают NULL. Поля id и brand_id обязательны.

## Проверка обязательных операций

Проверка выполнена через консоль на отдельном файле базы. Исходники скомпилированы с целевой версией Java 8.

| Сценарий | Результат |
| --- | --- |
| Вставка полной записи, нескольких записей и записи с частью столбцов | Записи добавлены. Пропущенные необязательные поля получили `NULL` |
| Выборка отдельных столбцов и выборка без совпадений | Столбцы выведены в порядке запроса. Пустая выборка показала заголовки и ноль записей |
| Обновление и удаление по условию | Каждая команда затронула ровно две подходящие записи |
| Неверные числа, даты, логические значения, имена и синтаксис | Консоль сообщила об ошибках и продолжила работу |
| Повторный первичный ключ, несуществующая марка и изменение используемого ключа марки | Запросы отклонены. Ошибка в одной строке пакетной вставки отменила весь пакет |
| Повторный запуск после изменений | Восстановлены обе марки и оставшийся автомобиль |
| Файл заблокирован для записи | Консоль сообщила об ошибке. Запрос `SELECT` показал последнее сохранённое состояние |
| Файл недоступен для чтения или обрезан | Программа вывела причину и завершилась. Содержимое файла сохранилось |

## Хранение и границы ответственности

- `Database` проверяет типы, ключи и ограничения до записи изменений.
- `SqlConsole` передаёт запрос парсеру и вызывает операцию базы. Изменения становятся видны в консоли после сохранения файла.
- `DatabaseFile` сериализует снимок базы во временный файл рядом с `database.ser`. Когда запись завершена, временный файл одним действием заменяет предыдущий снимок.
- При ошибке чтения `Main` показывает путь и причину и завершает запуск. Исходный файл остаётся на диске.
